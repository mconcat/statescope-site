statescope

Reading language model computation as circuits of state groups and transforms

Dictionary weights are available for Qwen3.5-4B and Qwen3.5-0.8B so far; more models will follow.

Code Weights for Qwen3.5-4B Weights for Qwen3.5-0.8B

Abstract

statescope is a method and a reader for reading a language model's computation as a circuit of multi-dimensional state groups and transforms. Each layer has two dictionaries: a state dictionary that writes the residual stream as a few active groups, and an MLP dictionary that writes the MLP as small gated linear transforms. We read mixers directly at the level of the model's own heads, and our reader is one Python file. We provide dictionary weights for Qwen3.5-4B and Qwen3.5-0.8B so far, with more models to follow.

In Qwen3.5-0.8B, we follow how the model decides to break a line in text wrapped to a fixed width, reading the trace as a sequence of geometric operations. One mixer head acts as a clock that is exactly linear in the number of characters since the line start. The count forms a curve in a plane inside one state group's frame, which MLP transforms read along directions with thresholds. Inside one mixer head in a later layer, a memory read that depends on the wrapping width is multiplied by a gate that depends on the count. Transforms then read a code for the remaining characters at a fixed distance before the line end.

In Qwen3.5-4B, we find a rule variable that represents which of two repetition rules a list follows as a plane inside one group's frame: one axis represents whether an item repeats an earlier item, and the other represents which item. We also examine a unit drawn at random that orders adjectives along a signed coordinate, from fatal through neutral words to vital.

Two dictionaries per layer

Qwen3.5-4B has {{b4.layers}} layers and width {{b4.width}}, while Qwen3.5-0.8B has {{model.layers}} layers and width {{model.width}}. Both dictionary sets have the same form, and the examples in this section come from the Qwen3.5-0.8B set. Each layer has a mixer, which is its GatedDeltaNet or attention sublayer, and an MLP. Each layer has a state dictionary and an MLP dictionary that were trained separately. Figure {{fig|layer}} shows where each one reads.

State dictionary: groups

The state dictionary represents the residual stream at two sites of its layer. The site resid_mid.L is the input of the norm before the MLP. The site resid_post.L is resid_mid plus the MLP output.

A group contains {{state.group_size}} directions that span a small subspace of the residual stream. Its frame is an orthonormal basis for that subspace, and a token's code is its {{state.group_size}} coordinates in the frame. Of the dictionary's {{state.groups}} groups, only the {{state.active}} with the largest written norm are active at each token, and their writes sum to represent the residual stream.

Group {{demo.l8_group}} at resid_post.8 is the first-token-of-a-line group: its frame contains {{demo.energy_group}} of the energy of L8 transform {{demo.l8_transform}}'s swapped write. Group {{demo.l9_group}} at resid_mid.9 is active on most tokens and carries information in its {{demo.frame_dim}} coordinates; the character count reaches the layer-9 transforms mostly through this frame.

We can read where a group is active and what it writes, or change its code and decode it back to a residual vector.

MLP dictionary: transforms

The MLP dictionary represents the layer's MLP operations, taking the post-norm MLP input and reconstructing the raw MLP output. Our MLP dictionary’s form, a sparse mixture of linear transforms (MOLT), follows Lindsey et al. (2025), with Oldfield et al. (2025) providing closely related work on decomposing MLP layers into sparse mixtures of linear maps.

A transform reads one direction of the MLP input, opens its gate when that reading passes a learned threshold, and writes a low-rank linear map of the input scaled by the gate value. Each Qwen3.5-0.8B layer has {{mlp.transforms}} transforms, with only a few gates open per token, and their writes sum to reconstruct the MLP output.

In Figure {{fig|lead}}, L8 transform {{demo.l8_transform}} marks the first token of each line: its gate opens on {{demo.t189_line_first}} of first tokens, {{demo.t189_newline}} of line-break tokens and {{demo.t189_other}} of other tokens. L9 transform {{demo.l9_transform_short}} fires on {{rate|L9 transform 410|40-49}} to {{rate|L9 transform 410|30-39}} of tokens at line lengths of 20 to 49 characters, falling to {{rate|L9 transform 410|70-79}} at 70 to 79 characters. L9 transform {{demo.l9_transform_long}} fires on {{rate|L9 transform 1749|60-69}} of tokens below 70 characters and {{rate|L9 transform 1749|90-99}} at 90 to 99 characters, as the bars in Figure {{fig|lead}} show.

We can read where a transform's gate opens and what it adds to the MLP output, or change its gate and recompute the output.

A transform is one gate times a low-rank linear write; the gate has a single read direction and a threshold. Rank belongs only to the write and carries how it varies with context; separate outcomes use separate transforms, such as one for “less” and another for “greater” when comparing two digits. For one rank-{{cmp.rank_357}} transform in Qwen3.5-4B, we measured that a unit with one fixed write direction would hold {{cmp.fixed_357_list}} of its write.

By design, the mixers are read directly at the level of the model's own heads and channels. We also trained a stateful transcoder, a dictionary with a state carried across tokens, on 18 GatedDeltaNet layers of the 0.8B model: in the line-counting computation it reproduced about one third of the true head's response, while one of the model's own heads (layer 9, head {{demo.head}}) carried the count about as well as the whole mixer. Attention is read at the level of heads.

A worked example: when to break a line

The demonstration uses the 0.8B set on texts wrapped to a fixed width. At the last word of a line, the model must predict a line break, so it must know how many characters the line already holds. Figure {{fig|lead}} shows three dictionary units that follow this count on one text.

Our worked example follows the line-counting task studied by Gurnee et al., which asks how a model decides where to break a line in text wrapped to a fixed width. We follow the same task in a different model, Qwen3.5-0.8B. In this model, head {{demo.head}} of the layer-9 GatedDeltaNet carries the count, and the layer-9 MLP reads it through one state group's frame.

We follow the computation from the line start to the decision. We read mixers directly through the model’s own heads and MLPs through transforms.

How the transforms read the count

The state dictionary and the transform’s gate use the residual stream divided by the same size. The frame part of the gate input is therefore exactly linear in the group’s code: we multiply the code by a direction derived from the dictionary weights, which we call the read direction. Figure {{fig|read}} shows that the two read directions differ but lie almost entirely in the plane of the count curve from Figure {{fig|curve}}.

Along the read direction of transform {{demo.l9_transform_short}}, the middle of the curve sticks out. Along the read direction of transform {{demo.l9_transform_long}}, only the far end sticks out.

The step from the count to the line-break decision can be read as a geometric operation: each transform reads the position on the curve along its own direction and compares that reading with a threshold.

One read direction makes transform {{demo.l9_transform_long}} switch on at a fixed count of {{lc.t1749_on_low}} to {{lc.t1749_on_high}} characters. The other makes transform {{demo.l9_transform_short}} switch on at about {{lc.t410_on_slope}} times the width and switch off at a fixed count of {{lc.t410_off_low}} to {{lc.t410_off_high}} characters.

Count and width form a sheet

From layer 8 through layer 11, count runs along each curve and width separates the curves at equal count, forming a sheet. The widths are separate from layer 8 onward, with no earlier stage of one shared count curve.

Per character, the across-width direction is {{lc.sheet_ratio_low}} to {{lc.sheet_ratio_high}} as large as the along-line direction, and {{lc.sheet_orth_low}} to {{lc.sheet_orth_high}} of it is orthogonal to that direction. At residual sites in layers 8 through 13, the mean count curve needs {{lc.components_min}} to {{lc.components_max}} components, and one state group’s frame holds {{lc.frame_low}} to {{lc.frame_high}} of the curve. Layers 10 and 11 carry the sheet without an MLP read-out; no transform in MLPs 9 through 13 reads width alone, and the layer-12 mixer uses the width.

A memory read meets a count gate

Head 13 of the layer-12 mixer has no decay and carries {{lc.h13_curve}} of the mixer’s count curve. Its write multiplies a width-dependent memory read, written by earlier lines and nearly constant within a line, by a count-dependent gate computed from the current token. Holding the gate at its mean shrinks the head’s curve to {{lc.h13_gate_fixed}} of its size.

Across {{lc.cz_tokens}} word-final tokens in texts wrapped at 100 characters, adding the difference between the mean memory reads at widths 40 and 100 produces a mean line-break margin peak at {{lc.cz_bump_count}} characters of {{lc.cz_bump_margin}}, compared with {{lc.cz_clean_there}} in the clean run, {{lc.cz_perm_there}} with permuted channels and {{lc.cz_end_clean}} at a clean line end. The first count where the mean margin exceeds -3 moves from {{lc.cz_cstar_clean}} to {{lc.cz_cstar_shift40}} with the width-40 read and to {{lc.cz_cstar_shift60}} with the width-60 read; with permuted channels it is {{lc.cz_cstar_perm}}.

This test shows that the memory read carries width information used by the decision. We infer that the product turns the count code into a remaining-characters code, which first appears immediately after this head’s write.

Swaps and doses confirm the first links

We use the swaps in Figure {{fig|chain}} and the dose slider in Figure {{fig|steer}} to causally confirm the first links of the trace.

Each item pairs {{demo.tokens_per_text}}-token texts ending on the same words. In every cell, the clean text's last line is full, at most {{demo.clean_short_max}} characters short of the width, so a line break is due. In the corrupt text a line break is not due.

A cell is a task setting defined by the wrapping width and how the corrupt text is made. The three cells are count:60, count:100 and width:100. Each cell contains {{demo.items_per_cell}} pairs.

  • In the count cells, the corrupt text's last line starts at a later word than the clean text's, chosen so that the line holds between {{demo.corrupt_fill_low}}% and {{demo.corrupt_fill_high}}% of the width at the last word, and the preceding lines are wrapped backward from that word at the same width, moving their line breaks too.
  • In the width cell, the corrupt text's last line starts at the same word as the clean text's, and the preceding lines are wrapped backward at {{demo.width_factor}} times the width.

The margin is the last-token logsumexp of newline-token logits minus the logsumexp of logits for tokens starting with a space. A higher margin favours a line break.

m = logsumexp(logits of newline tokens) - logsumexp(logits of tokens that start with a space)

A patch replaces a tensor in the clean run with a value built from the corrupt run and moved onto the clean run's token positions. Each row called a swap on this page is one such patched run of the clean texts. A share is the part of the clean/corrupt margin difference carried by the patched tensor. A share of 0 means that the patch changes nothing. A share of 1 means that the patch alone turns the clean run into the corrupt one.

share = mean(m_clean - m_patched) / mean(m_clean - m_corrupt)

Figure {{fig|chain}} ties each step to its swaps. In every step, the swap of one named unit stands next to the swap of the whole tensor it belongs to, measured by the same route. We read shares on the {{demo.items_per_half}} even-numbered items of each cell and chose the units on the odd-numbered items.

In the count cells, transform {{demo.l8_transform}} or group {{demo.l8_group}} carries about as much as the whole L8 MLP output through the L9 mixer. Head {{demo.head}}'s read alone gives a larger share than the whole mixer output. Transform {{demo.l9_transform_short}} carries the L9 MLP's effect in count:60, and transform {{demo.l9_transform_long}} carries it in width:100. The same computation is also visible in individual MLP neurons.

From the L9 mixer to the L9 transforms

The last link asks how the mixer's write reaches the L9 transforms. The whole mixer swap and head {{demo.head}}'s swap are each applied in full, only inside the {{demo.frame_dim}}-dimensional frame of state group {{demo.l9_group}} of resid_mid.9, or as the rest. The share is then read by three routes. For the first two, the changed resid_mid.9 enters the L9 MLP dictionary, and only the change in the selected transforms' writes is patched at the MLP output: once for the six L9 transforms we selected ({{demo.six}}), and once for transforms {{demo.l9_transform_short}} and {{demo.l9_transform_long}} alone. The third route is the same change with everything downstream.

The part inside group {{demo.l9_group}}'s frame moves the transforms about as much as the whole swap. The rest moves them little. We registered a pass rule for the mixer-to-MLP link. The rule requires at least {{rule.inside_min}} of the whole share inside the frame, at most {{rule.rest_max_fraction}} of it and at most {{rule.rest_max}} in the rest, and at most {{rule.random_max}} in random frames, in both count cells. Our verdict was that the rule holds for the route through the six transforms and holds only in part for the route through {{demo.l9_transform_short}} and {{demo.l9_transform_long}} alone, because we recorded a share of {{rule.recorded_rest}} for the rest in count:100 through those two transforms.

Four examples from Qwen3.5-4B

We studied Qwen/Qwen3.5-4B across {{b4.layers}} layers of width {{b4.width}}, using the same reader as the 0.8B set. Each state dictionary has {{b4.groups}} groups of {{b4.group_size}} directions, and each MLP dictionary has {{b4.transforms}} transforms. These four examples show what its units hold.

Two axes hold a repetition rule

We followed the repetition task from Yang et al. (2025), using word lists with two examples of a rule: ABA repeats the first item, as in “sun, tree, sun”, and ABB repeats the preceding item, as in “sun, tree, tree”. At the third item, group {{aba.group}} at resid_post.{{aba.site_layer}} holds a plane with a repeat axis, where ABA is {{aba.aba_common}}, ABB is {{aba.abb_common}} and a new word is {{aba.ctrl_common}}, and a which-item axis, where ABA is {{aba.aba_rule}} and ABB is {{aba.abb_rule}}.

At resid_post.13, group {{aba.g13}} is selected on {{aba.sel_aba}} of ABA third items, {{aba.sel_abb}} of ABB third items and {{aba.sel_ctrl}} of new-word third items, so selection marks repetition while the coordinates distinguish the rules.

Attention head 14 of layer 15 carries the variable to the last position through two read directions, with gains of {{aba.read1_gain}} for the repeat axis and {{aba.read2_gain}} for the which-item axis, against a random-direction median of {{aba.random_gain}} and maximum of {{aba.random_gain_max}}. Moving between the rules inside this frame, only in what the layer-15 mixer reads, moves the last position by {{aba.move_low}} to {{aba.move_high}} of the natural difference in the destination frames; an equally sized move in a random frame gives {{aba.move_random_low}} to {{aba.move_random_high}}.

A related later study is Li and Webb.

The state holds a running average

We measured the mean state at the answer position, resid_mid.15, for prompts with {{avg.lines}} example lines of mixed types in all {{avg.histories}} orders, followed by a query. The states lie close to a plane with corners for prompts containing only ABA, only ABB or only lines without repetition; differences in type counts explain {{avg.count_distance}} of the variance in distances between histories, while shared ending length explains {{avg.shared_suffix}}.

Each added line moves the state toward its type in a running average, with measured shrink factors of {{avg.shrink2}}, {{avg.shrink3}}, {{avg.shrink4}} and {{avg.shrink5}} for two through five lines, compared with {{avg.ideal2}}, {{avg.ideal3}}, {{avg.ideal4}} and {{avg.ideal5}} for an exact running average. Head 14 in layer 15 gives {{avg.attention_third}} of its attention to the example lines’ third items and writes an attention-weighted sum of one vector per type, with R² {{avg.mixture_r2}} compared with {{avg.equal_r2}} for equal weights.

The answer follows the same quantity: the plane’s two coordinates predict the difference in answer logits between the two rules with R² {{avg.answer_r2}}. The frames we found with two examples also hold this structure: among 16,384 frames, groups {{aba.read1_dest}}, {{aba.read2_dest_b}} and {{aba.read2_dest_a}} rank {{avg.rank_858}}, {{avg.rank_14020}} and {{avg.rank_680}} for variation between histories, although we did not choose them using these data.

A signed coordinate orders words by lethality

We drew units at random with a fixed seed and traced them by hand, including group {{leth.group}} at resid_post.{{leth.layer}}. For {{leth.words}} adjectives completing “It was a W”, its fourth coordinate orders words by lethality: fatal {{leth.fatal}}, lethal {{leth.lethal}}, deadly {{leth.deadly}}, crucial {{leth.crucial}}, safe {{leth.safe}}, alive {{leth.alive}} and vital {{leth.vital}}.

The second coordinate is negative for vital {{leth.c2_vital}}, fatal {{leth.c2_fatal}} and pivotal {{leth.c2_pivotal}}; our reading is that the word says something is decisive.

Moving “vital” along the fourth coordinate to the value of a death word shifts the next-word predictions toward nouns such as “mistake”, “error” and “accident”, away from “role”, “part” and “component”. The margin moves by {{leth.move}} nats toward the death word in {{leth.move_toward}} of {{leth.pairs}} pairs, covering {{leth.move_share}} of the gap; equally sized moves along random directions inside and outside the frame change it by {{leth.other_low}} to {{leth.other_high}} nats.

From the same draw, group {{tab.group}} at resid_post.{{tab.layer}} has a coordinate for whether another column follows in a Markdown table’s separator row: {{tab.more_low}} to {{tab.more_high}} when one follows, against {{tab.last_low}} to {{tab.last_high}} in the last column. Attention head 4 of layer 15 finds the header cell by its cell index, and replacing a separator cell’s residual stream with another cell’s redirects the head in {{tab.reaim}} of {{tab.reaim_n}} cases. Moving within the group’s frame changes that choice by at most {{tab.route}} of the gap.

In group {{ex.group}} at resid_mid.{{ex.layer}}, “such as”, “like” and “e.g.” occupy one corner of the frame, and the listed examples occupy another. Moving a sentence where “like” is a verb to the coordinates of its twin where “like” introduces examples raises preference for the example continuation by {{ex.move}} nats on average over {{ex.pairs}} pairs.

Two transforms read opposite comparison outcomes

We used lists with a digit in the same slot on each line, such as dates or weights, and compared the current digit with the digit in earlier lines. At resid_mid.7, group {{cmp.group}} already separates less and greater along one axis, while repeated values lie apart along a second axis; this plane holds {{cmp.plane_share}} of the variance of {{cmp.cells}} cell means.

Transform {{b4u.js_transform}} reads the less direction and transform 472 reads the greater direction, with cosine {{cmp.cosine}} between their read directions inside the frame and shares of {{cmp.inside_357}} and {{cmp.inside_472}} lying in the plane. The layer-7 MLP then pushes the state further along the same axis.

A transform has one read direction and a threshold, so separate outcomes use separate transforms, here {{b4u.js_transform}} and 472; rank belongs to the linear write and carries how that write varies with context. Transform {{b4u.js_transform}} has rank {{cmp.rank_357}}, and one fixed write direction would hold {{cmp.fixed_357_list}} of its write on lists and {{cmp.fixed_357_js}} on JavaScript comparisons, against {{cmp.fixed_472_list}} and {{cmp.fixed_472_js}} for transform 472. The write that a fixed direction would miss varies with the surrounding text, the operator and the distance between the digits.

One group sets how a function body opens

We asked the model to infer a rule from input-output cases and complete a Python function, examining group {{b4u.rule_group}} at resid_mid.{{b4u.rule_layer}} before the function body. Moving along one direction in its frame makes the first body token # in {{st.hash_dose4}} of prompts, and the output layer reads this direction almost directly as opening the line with a comment sign. The model’s own continuation then writes reasoning in comments followed by the rule.

In one run on {{st.prompts}} prompts, correct-rule rates were {{st.base}} without the move, {{st.move}} with the move and {{st.forced}} with the first body token forced to # and no move. We selected the unit by contrasting prompts with and without “Reply with code only.”.

Numbers per layer

FVU means fraction of variance unexplained: squared reconstruction error divided by squared deviation from the per-dimension mean of each held-out split. State FVU uses raw residual units, and MLP FVU uses raw MLP output units.

We re-measured state FVU at resid_mid and resid_post and MLP FVU on all tokens of four held-out splits except position 0, the first position of each sequence, giving {{fvu.tokens}} tokens per layer for Qwen3.5-0.8B and {{b4.fvu_tokens}} for Qwen3.5-4B. We recorded the other MLP FVU column, transforms on per token, and transforms alive at training on a held-out shard of each layer’s training capture with position 0 included, so the two MLP FVU columns use different tokens.

Transforms on per token is the mean number of transforms whose gate is open at a token, and transforms alive counts those that fired on at least one token of that shard. In the figures, solid lines with filled marks show re-measured values, while dashed lines, open marks, and bars show values recorded at training.
