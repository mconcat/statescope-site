Reading language model computation as circuits of state groups and transforms

Dictionary weights are available for Qwen3.5-4B and Qwen3.5-0.8B so far; more models will follow.

Code Weights for Qwen3.5-4B Weights for Qwen3.5-0.8B

Abstract

We introduce statescope, a method and a reader for reading language model computation through per-layer dictionaries as a circuit of state groups and transforms. Each layer has two dictionaries: a state dictionary that writes the residual stream as a few active groups of directions, and an MLP dictionary that writes the layer’s MLP as a sum of small gated linear operations. The reader is one Python file. We provide sets of dictionary weights for Qwen3.5-4B and Qwen3.5-0.8B so far, and more models will follow.

We follow a line-break decision in Qwen3.5-0.8B through named units. A layer-8 transform fires on the first token of each line, and a head of the layer-9 mixer carries the count of characters since then. Two layer-9 transforms turn that count into the line-break decision. In text wrapped at 60 characters, swapping only the first transform's write through the mixer carries {{share|count:60|l8/t189}} of the change in the model's preference for a line break, and swapping the whole layer-8 MLP output the same way carries {{share|count:60|l8/mlp8_true}}.

We steered Qwen3.5-4B with single state groups. In a Python rule-completion task, moving the residual stream inside one group's frame raised the rate of correct rules from {{b4u.rule_before}} to {{b4u.rule_after}}.

Two dictionaries per layer

Qwen3.5-4B has {{b4.layers}} layers and width {{b4.width}}, while Qwen3.5-0.8B has {{model.layers}} layers and width {{model.width}}. Both dictionary sets have the same form, and the examples in this section come from the Qwen3.5-0.8B set. Each layer has a mixer, which is its GatedDeltaNet or attention sublayer, and an MLP. Each layer has a state dictionary and an MLP dictionary that were trained separately. Figure {{fig|layer}} shows where each one reads.

State dictionary: groups

The state dictionary represents the residual stream at two sites of its layer. The site resid_mid.L is the input of the norm before the MLP. The site resid_post.L is resid_mid plus the MLP output.

A group contains {{state.group_size}} directions that span a small subspace of the residual stream. Its frame is an orthonormal basis for that subspace, and a token's code is its {{state.group_size}} coordinates in the frame. Of the dictionary's {{state.groups}} groups, only the {{state.active}} with the largest written norm are active at each token, and their writes sum to represent the residual stream.

Group {{demo.l8_group}} at resid_post.8 is the first-token-of-a-line group: its frame contains {{demo.energy_group}} of the energy of L8 transform {{demo.l8_transform}}'s swapped write. Group {{demo.l9_group}} at resid_mid.9 is active on most tokens and carries information in its {{demo.frame_dim}} coordinates; the character count reaches the layer-9 transforms mostly through this frame.

We can read where a group is active and what it writes, or change its code and decode it back to a residual vector.

MLP dictionary: transforms

The MLP dictionary represents the layer's MLP operations, taking the post-norm MLP input and reconstructing the raw MLP output. Our MLP dictionary’s form, a sparse mixture of linear transforms (MOLT), follows Lindsey et al. (2025), with Oldfield et al. (2025) providing closely related work on decomposing MLP layers into sparse mixtures of linear maps.

A transform reads one direction of the MLP input, opens its gate when that reading passes a learned threshold, and writes a low-rank linear map of the input scaled by the gate value. Each Qwen3.5-0.8B layer has {{mlp.transforms}} transforms, with only a few gates open per token, and their writes sum to reconstruct the MLP output.

In Figure {{fig|lead}}, L8 transform {{demo.l8_transform}} marks the first token of each line: its gate opens on {{demo.t189_line_first}} of first tokens, {{demo.t189_newline}} of line-break tokens and {{demo.t189_other}} of other tokens. L9 transform {{demo.l9_transform_short}} fires on {{rate|L9 transform 410|40-49}} to {{rate|L9 transform 410|30-39}} of tokens at line lengths of 20 to 49 characters, falling to {{rate|L9 transform 410|70-79}} at 70 to 79 characters. L9 transform {{demo.l9_transform_long}} fires on {{rate|L9 transform 1749|60-69}} of tokens below 70 characters and {{rate|L9 transform 1749|90-99}} at 90 to 99 characters, as the bars in Figure {{fig|lead}} show.

We can read where a transform's gate opens and what it adds to the MLP output, or change its gate and recompute the output.

By design, the mixers are read directly at the level of the model's own heads and channels. We also trained a stateful transcoder, a dictionary with a state carried across tokens, on 18 GatedDeltaNet layers of the 0.8B model: in the line-counting computation it reproduced about one third of the true head's response, while one of the model's own heads (layer 9, head {{demo.head}}) carried the count about as well as the whole mixer. Attention is read at the level of heads.

A worked example: when to break a line

The demonstration uses the 0.8B set on texts wrapped to a fixed width. At the last word of a line, the model must predict a line break, so it must know how many characters the line already holds. Figure {{fig|lead}} shows three dictionary units that follow this count on one text.

Our worked example follows the line-counting task studied by Gurnee et al., which asks how a model decides where to break a line in text wrapped to a fixed width. We follow the same task in a different model, Qwen3.5-0.8B. In this model, head {{demo.head}} of the layer-9 GatedDeltaNet carries the count, and the layer-9 MLP reads it through one state group's frame.

Pairs of texts and the margin

Each item pairs {{demo.tokens_per_text}}-token texts ending on the same words. In every cell, the clean text's last line is full, at most {{demo.clean_short_max}} characters short of the width, so a line break is due. In the corrupt text a line break is not due.

A cell is a task setting defined by the wrapping width and how the corrupt text is made. The three cells are count:60, count:100 and width:100. Each cell contains {{demo.items_per_cell}} pairs.

  • In the count cells, the corrupt text's last line starts at a later word than the clean text's, chosen so that the line holds between {{demo.corrupt_fill_low}}% and {{demo.corrupt_fill_high}}% of the width at the last word, and the preceding lines are wrapped backward from that word at the same width, moving their line breaks too.
  • In the width cell, the corrupt text's last line starts at the same word as the clean text's, and the preceding lines are wrapped backward at {{demo.width_factor}} times the width.

The margin is the last-token logsumexp of newline-token logits minus the logsumexp of logits for tokens starting with a space. A higher margin favours a line break.

m = logsumexp(logits of newline tokens) - logsumexp(logits of tokens that start with a space)

A patch replaces a tensor in the clean run with a value built from the corrupt run and moved onto the clean run's token positions. Each row called a swap on this page is one such patched run of the clean texts. A share is the part of the clean/corrupt margin difference carried by the patched tensor. A share of 0 means that the patch changes nothing. A share of 1 means that the patch alone turns the clean run into the corrupt one.

share = mean(m_clean - m_patched) / mean(m_clean - m_corrupt)

The chain, step by step

  1. Transform {{demo.l8_transform}} of the L8 MLP dictionary fires on the first token of a line. Its write lies mostly inside the frame of state group {{demo.l8_group}} of resid_post.8, the first-token-of-a-line group.
  2. The model's L9 mixer reads that write. Swapping only transform {{demo.l8_transform}}'s write or only group {{demo.l8_group}} moves the answer about as much as swapping the whole L8 MLP output in the count cells. GatedDeltaNet head {{demo.head}} carries the count inside the mixer.
  3. Transforms {{demo.l9_transform_short}} and {{demo.l9_transform_long}} of the L9 MLP dictionary turn the count into the line-break decision. Transform {{demo.l9_transform_short}} is on while the line is short, and transform {{demo.l9_transform_long}} is on once it is long. What the L9 transforms read of the mixer's write lies mostly inside the {{demo.frame_dim}}-dimensional frame of state group {{demo.l9_group}} of resid_mid.9.

Figure {{fig|chain}} ties each step to its swaps. In every step, the swap of one named unit stands next to the swap of the whole tensor it belongs to, measured by the same route. We read shares on the {{demo.items_per_half}} even-numbered items of each cell and chose the units on the odd-numbered items.

In the count cells, transform {{demo.l8_transform}} or group {{demo.l8_group}} carries about as much as the whole L8 MLP output through the L9 mixer. Head {{demo.head}}'s read alone gives a larger share than the whole mixer output. Transform {{demo.l9_transform_short}} carries the L9 MLP's effect in count:60, and transform {{demo.l9_transform_long}} carries it in width:100. The same computation is also visible in individual MLP neurons.

The character count as a curve inside one state group's frame

The chain reached state group {{demo.l9_group}} at resid_mid.9. It showed that the part of the layer-9 mixer's write inside this group's frame moves the layer-9 MLP transforms about as much as the whole write. How the transforms read the count

The state dictionary and the transform’s gate use the residual stream divided by the same size. The frame part of the gate input is therefore exactly linear in the group’s code: we multiply the code by a direction derived from the dictionary weights, which we call the read direction. Figure {{fig|read}} shows that the two read directions differ but lie almost entirely in the plane of the count curve from Figure {{fig|curve}}.

Along the read direction of transform {{demo.l9_transform_short}}, the middle of the curve sticks out. Along the read direction of transform {{demo.l9_transform_long}}, only the far end sticks out.

The step from the count to the line-break decision can be read as a geometric operation: each transform reads the position on the curve along its own direction and compares that reading with a threshold.

One swap, item by item

We next test the chain shown in these two figures causally by replacing one unit’s value with its value on a second text and measuring how far the line-break decision moves. A share is a ratio of two means over items. Figure {{fig|items}} shows what is behind one share: for each of the {{demo.items_per_cell}} items of a cell, the margin of the clean run, of the corrupt run, and of the clean run with one swap.

From the L9 mixer to the L9 transforms

The last link asks how the mixer's write reaches the L9 transforms. The whole mixer swap and head {{demo.head}}'s swap are each applied in full, only inside the {{demo.frame_dim}}-dimensional frame of state group {{demo.l9_group}} of resid_mid.9, or as the rest. The share is then read by three routes. For the first two, the changed resid_mid.9 enters the L9 MLP dictionary, and only the change in the selected transforms' writes is patched at the MLP output: once for the six L9 transforms we selected ({{demo.six}}), and once for transforms {{demo.l9_transform_short}} and {{demo.l9_transform_long}} alone. The third route is the same change with everything downstream.

Table: the link comparison in the three cells {{table|link}}

The part inside group {{demo.l9_group}}'s frame moves the transforms about as much as the whole swap. The rest moves them little. On even-numbered items, for the whole mixer swap, the rest carries {{link.rest_six.count60}} in count:60, {{link.rest_six.count100}} in count:100 and {{link.rest_six.width100}} in width:100 through the six transforms. Through the two transforms alone, the rest carries {{link.rest_two.count60}}, {{link.rest_two.count100}} and {{link.rest_two.width100}}. A random {{demo.frame_dim}}-dimensional frame carries at most {{link.random_six_max}} through the six transforms and {{link.random_two_max}} through the two.

With everything downstream, the rest carries {{link.rest_down.count60}} in count:60, {{link.rest_down.count100}} in count:100 and {{link.rest_down.width100}} in width:100. The frame is therefore not the only route to the answer. The downstream shares of the two parts do not add up to the whole.

We registered a pass rule for the mixer-to-MLP link. The rule requires at least {{rule.inside_min}} of the whole share inside the frame, at most {{rule.rest_max_fraction}} of it and at most {{rule.rest_max}} in the rest, and at most {{rule.random_max}} in random frames, in both count cells. Our verdict was that the rule holds for the route through the six transforms and holds only in part for the route through {{demo.l9_transform_short}} and {{demo.l9_transform_long}} alone, because we recorded a share of {{rule.recorded_rest}} for the rest in count:100 through those two transforms.

Steering one unit by a dose

A dose α scales the change from a unit’s clean value toward its corrupt value, aligned to the clean text’s token positions, and we varied the dose across {{steer.doses}} values from {{steer.dose_min}} to {{steer.dose_max}} for {{steer.units}} units. The shares in Figure {{fig|steer}} are over all {{steer.items}} items of a cell, while we read shares elsewhere on the page on the {{demo.items_per_half}} even-numbered items, so the numbers differ. For L8 transform {{demo.l8_transform}} in count:60, over all {{steer.items}} items, we observed a share of {{steer|count:60|l8/t189|1}} at the full swap and {{steer|count:60|l8/t189|2}} at α = {{steer.dose_max}}, so going past the full swap adds nothing there, while the share of {{steer|count:60|l8/t189|-1}} at α = {{steer.dose_min}} shows that a negative dose is not the mirror image of a positive one.

What we did with Qwen3.5-4B units

Our set for Qwen/Qwen3.5-4B covers {{b4.layers}} layers of width {{b4.width}}. Each layer has a state dictionary with {{b4.groups}} groups of {{b4.group_size}} directions and an MLP dictionary with {{b4.transforms}} transforms, read with the same reader as the Qwen3.5-0.8B set. This section shows three experiments we did with these units.

Changing how the model completes Python rules

We asked the model to infer a rule from input-output examples and complete a Python function across {{b4u.rule_families}} rule families it had not been tuned on. At the token before the function body, we shifted the residual stream within the frame of group {{b4u.rule_group}} at resid_mid.{{b4u.rule_layer}}. The model then reasoned in comments before writing the rule, and the rate of correct rules rose from {{b4u.rule_before}} to {{b4u.rule_after}} over {{b4u.rule_generations}} generations.

In a separate comparison, forcing the first body token to # gave a correct-rule rate of {{b4u.rule_forced}}, compared with {{b4u.rule_unit_same_run}} for the group shift, with the difference inside the interval.

Such groups can also be combined: on held-out tasks, applying one group per behaviour throughout generation changed comment density from {{b4x.comment_before}} to {{b4x.comment_after}}, non-Latin comments from {{b4x.nonlatin_before}} to {{b4x.nonlatin_after}}, and input validation from {{b4x.validation_before}} to {{b4x.validation_after}}.

With the shift applied during generation, this sample starts with if n == 2: return 5 and elif n == 8: return 65, works out the pattern in comments, and then writes return n * n + 1. Without the shift, the model continues listing cases up to a fourth branch.

Changing which repetition rule the model follows

The ABA / ABB task and the three-stage picture of how a model solves it come from Yang et al. (2025), and we followed this task in Qwen3.5-4B.

We gave the model comma-separated words with two examples of a repetition rule: ABA repeats the first item, as in “sun, tree, sun”, while ABB repeats the second, as in “sun, tree, tree”. At layers {{b4u.aba_layer_first}} to {{b4u.aba_layer_last}}, one group carried {{b4u.aba_one_lo}} to {{b4u.aba_one_hi}} of the effect of swapping the full residual difference between the rules, four groups carried {{b4u.aba_four_lo}} to {{b4u.aba_four_hi}}, and sixteen groups carried {{b4u.aba_sixteen_lo}} to {{b4u.aba_sixteen_hi}}.

We shifted the residual stream within the frame of group {{b4u.aba_group}} at resid_post.{{b4u.aba_layer}} by the mean difference between the rules. This changed ABA to ABB in {{b4u.aba_to_abb}} of prompts, or {{b4u.aba_to_abb_twice}} at twice the shift. The share changing from ABB to ABA was {{b4u.abb_to_aba}}, or {{b4u.abb_to_aba_twice}} at twice the shift.

A related study is Li and Webb, “What drives the emergence of symbolic mechanisms in large language models?”

Reading a transform that compares symbols

Transform {{b4u.js_transform}} in the layer-{{b4u.js_layer}} MLP dictionary fires when the current symbol is smaller than the symbol in the same slot of earlier lines. Its sibling transforms cover the other comparisons: transform {{b4x.equal_transform}} fires for “equal”, and transform {{b4x.greater_transform}} fires for “greater”.

We traced a circuit by hand for a JavaScript ternary expression, which chooses between two values according to a condition, and the same transform ranked first. At layer {{b4u.js_layer}}, the MLP dictionary’s reconstruction carried {{b4u.js_share}} of the MLP’s contribution, with an interval of {{b4u.js_lo}} to {{b4u.js_hi}}. Two MLP neurons carried {{b4u.js_neurons}} of the same contribution.

Using it

Python 3.12 or newer is required. This command adds transformers, accelerate and flash-linear-attention, which capture and the demonstration need:

sh
pip install -e '.[model]'

This command downloads one layer of the 4B set:

sh
{{b4.download_one_layer}}

The reader is the single file src/statescope/reader.py. It can be copied next to the weights. capture returns resid_mid, mlp_out and resid_post for the requested layer with position 0 dropped.

python
{{reader.example_4b}}

The 4B model in bf16 plus one layer's two dictionaries needed more than {{b4.gpu_gib}} GiB of GPU memory. The 0.8B set is read the same way with Qwen/Qwen3.5-0.8B and its own folder, with {{mlp.transforms}} transforms per layer and layers {{model.first_layer}} to {{model.last_layer}}.

This command downloads the 0.8B weights:

sh
hf download mconcat/statescope-qwen3.5-0.8b --local-dir <folder>

The first command checks all {{set.files}} files against the manifest. The second re-runs the traced line-count chain; it ran in under two minutes on one RTX 5090, including model loading.

sh
python demo/verify_release.py --release <folder>
python demo/line_count.py --release <folder> --device cuda:0 --out <folder for the result>

Without flash-linear-attention, transformers silently uses a slow GatedDeltaNet reference implementation. The repository contains the reader, a demonstration and tests. Training code will follow.

Numbers per layer

FVU means fraction of variance unexplained: squared reconstruction error divided by squared deviation from the per-dimension mean of each held-out split. State FVU uses raw residual units, and MLP FVU uses raw MLP output units.

We re-measured state FVU at resid_mid and resid_post and MLP FVU on all tokens of four held-out splits except position 0, the first position of each sequence, giving {{fvu.tokens}} tokens per layer for Qwen3.5-0.8B and {{b4.fvu_tokens}} for Qwen3.5-4B. We recorded the other MLP FVU column, transforms on per token, and transforms alive at training on a held-out shard of each layer’s training capture with position 0 included, so the two MLP FVU columns use different tokens.

Transforms on per token is the mean number of transforms whose gate is open at a token, and transforms alive counts those that fired on at least one token of that shard. In the figures, solid lines with filled marks show re-measured values, while dashed lines, open marks, and bars show values recorded at training.
