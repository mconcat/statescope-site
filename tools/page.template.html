statescope

Per-layer dictionaries for the language model Qwen3.5-0.8B: a state dictionary of the residual stream and an MLP dictionary of gated low-rank transforms at each of its {{model.layers}} layers, a reader in one Python file, and one computation followed through named units.

statescope is a reader in one Python file and a set of dictionary weights for {{set.model}}. Each of the model's {{model.layers}} layers has two dictionaries that were trained separately. The state dictionary writes the residual stream as a few active groups of directions. The MLP dictionary writes the layer's MLP as a sum of small gated linear operations called transforms.

This page follows one computation through these units: how the model decides to break a line in text wrapped to a fixed width. One transform at layer 8 fires on the first token of each line. A head of the layer-9 mixer carries the count of characters since then. Two transforms at layer 9 turn the count into the line-break decision: one is on while the line is short, and the other is on once it is long. In text wrapped at 60 characters, swapping only the first transform's write through the mixer carries {{share|count:60|l8/t189}} of the change in the model's preference for a line break, and swapping the whole layer-8 MLP output the same way carries {{share|count:60|l8/mlp8_true}}.

The evidence is narrow. The set covers one model and one dictionary seed, and it has no dictionaries for the mixers. The demonstration covers one easy task with dedicated MLP neurons and is not evidence that dictionary units are better than neurons. The trainers are not in the repository, and the per-layer numbers cannot be recomputed from the published files. The section Limits lists all of this.

Two dictionaries per layer

The base model has {{model.layers}} layers and width {{model.width}}. Each layer has a mixer, which is its GatedDeltaNet or attention sublayer, and an MLP. Each layer has a state dictionary and an MLP dictionary that were trained separately. Figure {{fig|layer}} shows where each one reads.

The state dictionary represents the residual stream at two sites of its layer. A residual stream site is a location between the mixer and the MLP or after the MLP where a state dictionary reads the residual stream. The site resid_mid.L is the input of the norm before the MLP. The site resid_post.L is resid_mid plus the MLP output.

The MLP dictionary represents the layer's MLP operations, taking the post-norm MLP input and reconstructing the raw MLP output. It uses the sparse mixture of linear transforms, or MOLT, from the public crosslayer-transcoder code.

In the state dictionary, the input is divided by its own size, and it is then standardised with a mean vector and one scale per site. Each layer's dictionary was trained on {{state.train_tokens}} tokens over {{state.train_steps}} steps.

The MLP dictionary uses a JumpReLU gate. Each transform has free read and write matrices. There is no skip connection. Training uses a tanh sparsity penalty. Training used {{mlp.train_steps}} steps of {{mlp.step_tokens}} tokens, or {{mlp.train_million_tokens}} million tokens, per layer. The learning rate was {{mlp.learning_rate}}. The sparsity penalty coefficient was {{mlp.penalty_main}} for layers {{model.first_layer}} to {{mlp.penalty_main_last_layer}}. Layer {{model.last_layer}} used {{mlp.penalty_last}} in a separate run.

No mixer dictionaries. This set contains no dictionaries for the mixers. Where the example below passes through a mixer, it is measured in the model's own mixer.

The set contains {{set.files}} weight and config files. State dictionaries occupy about {{set.state_gib}} GiB, and MLP dictionaries occupy about {{set.mlp_gib}} GiB. The repository contains the reader, a demonstration and tests. The trainers for this set are not in the repository.

A worked example: when to break a line

The task uses texts wrapped to a fixed width. At the last word of a line, the model must predict a line break, so it must know how many characters the line already holds. Figure {{fig|lead}} shows three dictionary units that follow this count on one text.

The original project found the chain described in this section. The script demo/line_count.py uses its chosen transform, group and head and re-measures their effects. It does not search for them. The shares, firing rates and per-item margins on this page are the output of one run of that script, read from its result.json and result.safetensors. No model runs in the browser.

Pairs of texts and the margin

Each item pairs {{demo.tokens_per_text}}-token texts ending on the same words. In every cell, the clean text's last line is full, at most {{demo.clean_short_max}} characters short of the width, so a line break is due. In the corrupt text a line break is not due.

A cell is a task setting defined by the wrapping width and how the corrupt text is made. The three cells are count:60, count:100 and width:100. Each cell contains {{demo.items_per_cell}} pairs.

  • In the count cells, the corrupt text's last line starts at a later word than the clean text's, chosen so that the line holds between {{demo.corrupt_fill_low}}% and {{demo.corrupt_fill_high}}% of the width at the last word, and the preceding lines are wrapped backward from that word at the same width, moving their line breaks too.
  • In the width cell, the corrupt text's last line starts at the same word as the clean text's, and the preceding lines are wrapped backward at {{demo.width_factor}} times the width.

The margin is the last-token logsumexp of newline-token logits minus the logsumexp of logits for tokens starting with a space. A higher margin favours a line break.

m = logsumexp(logits of newline tokens) - logsumexp(logits of tokens that start with a space)

A patch replaces a tensor in the clean run with a value built from the corrupt run and moved onto the clean run's token positions. Each row called a swap on this page is one such patched run of the clean texts. A share is the part of the clean/corrupt margin difference carried by the patched tensor. A share of 0 means that the patch changes nothing. A share of 1 means that the patch alone turns the clean run into the corrupt one.

share = mean(m_clean - m_patched) / mean(m_clean - m_corrupt)

The chain, step by step

  1. Transform {{demo.l8_transform}} of the L8 MLP dictionary fires on the first token of a line. Its write lies mostly inside the frame of state group {{demo.l8_group}} of resid_post.8, the first-token-of-a-line group.
  2. The model's L9 mixer reads that write. Swapping only transform {{demo.l8_transform}}'s write or only group {{demo.l8_group}} moves the answer about as much as swapping the whole L8 MLP output in the count cells. GatedDeltaNet head {{demo.head}} carries the count inside the mixer.
  3. Transforms {{demo.l9_transform_short}} and {{demo.l9_transform_long}} of the L9 MLP dictionary turn the count into the line-break decision. Transform {{demo.l9_transform_short}} is on while the line is short, and transform {{demo.l9_transform_long}} is on once it is long. What the L9 transforms read of the mixer's write lies mostly inside the {{demo.frame_dim}}-dimensional frame of state group {{demo.l9_group}} of resid_mid.9.

An easy task. This is an easy task for which the model has dedicated MLP neurons. The demonstration is not evidence that dictionary units are better than neurons.

Figure {{fig|chain}} ties each step to its swaps. In every step, the swap of one named unit stands next to the swap of the whole tensor it belongs to, measured by the same route.

In the count cells, transform {{demo.l8_transform}} or group {{demo.l8_group}} carries about as much as the whole L8 MLP output through the L9 mixer. Head {{demo.head}}'s read alone gives a larger share than the whole mixer output. Transform {{demo.l9_transform_short}} carries the L9 MLP's effect in count:60, and transform {{demo.l9_transform_long}} carries it in width:100.

Transform {{demo.l8_transform}} fires on {{demo.t189_line_first}} of line-first tokens, {{demo.t189_newline}} of line-break tokens and {{demo.t189_other}} of other tokens. Of the energy in its swapped write, {{demo.energy_group}} lies inside group {{demo.l8_group}}'s frame. The largest value among five random frames is {{demo.energy_random_max}}. The chance value for a {{demo.frame_dim}}-dimensional frame in {{demo.chance_dims}} dimensions is {{demo.chance_value}}.

Transform {{demo.l9_transform_short}} fires on {{rate|L9 transform 410|40-49}} to {{rate|L9 transform 410|30-39}} of tokens when a line holds 20 to 49 characters. It fires on {{rate|L9 transform 410|60-69}} at 60 to 69 characters and {{rate|L9 transform 410|70-79}} at 70 to 79. Transform {{demo.l9_transform_long}} fires on {{rate|L9 transform 1749|60-69}} below 70 characters, {{rate|L9 transform 1749|80-89}} at 80 to 89 and {{rate|L9 transform 1749|90-99}} at 90 to 99.

One swap, item by item

A share is a ratio of two means over items. Figure {{fig|items}} shows what is behind one share: for each of the {{demo.items_per_cell}} items of a cell, the margin of the clean run, of the corrupt run, and of the clean run with one swap.

Rounding. Single-item margins of dictionary swaps are reproducible only to about {{demo.margin_repro}}. Shares are reproducible only to about {{demo.share_repro}}. A patched tensor is rounded to bf16. A {{demo.relative_difference}} relative difference between implementations flips some rounded elements.

From the L9 mixer to the L9 transforms

The last link asks how the mixer's write reaches the L9 transforms. The whole mixer swap and head {{demo.head}}'s swap are each applied in full, only inside the {{demo.frame_dim}}-dimensional frame of state group {{demo.l9_group}} of resid_mid.9, or as the rest. The share is then read by three routes. For the first two, the changed resid_mid.9 enters the L9 MLP dictionary, and only the change in the selected transforms' writes is patched at the MLP output: once for the six L9 transforms selected by the original project ({{demo.six}}), and once for transforms {{demo.l9_transform_short}} and {{demo.l9_transform_long}} alone. The third route is the same change with everything downstream.

The part inside group {{demo.l9_group}}'s frame moves the transforms about as much as the whole swap. The rest moves them little. On even-numbered items, for the whole mixer swap, the rest carries {{link.rest_six.count60}} in count:60, {{link.rest_six.count100}} in count:100 and {{link.rest_six.width100}} in width:100 through the six transforms. Through the two transforms alone, the rest carries {{link.rest_two.count60}}, {{link.rest_two.count100}} and {{link.rest_two.width100}}. A random {{demo.frame_dim}}-dimensional frame carries at most {{link.random_six_max}} through the six transforms and {{link.random_two_max}} through the two.

Group {{demo.l9_group}} is dense. State group {{demo.l8_group}} is sparse, but not every group is sparse. Some groups encountered by the original project on this task are dense {{demo.frame_dim}}-dimensional coordinates active on most tokens. They carry information in their coordinates. Group {{demo.l9_group}} is one of these dense groups, not a sparse feature.

With everything downstream, the rest carries {{link.rest_down.count60}} in count:60, {{link.rest_down.count100}} in count:100 and {{link.rest_down.width100}} in width:100. The frame is therefore not the only route to the answer. The downstream shares of the two parts do not add up to the whole.

The original project registered a pass rule for the mixer-to-MLP link before measuring it. The part inside the frame must keep at least {{rule.inside_min}} of the whole share. The rest must keep at most {{rule.rest_max_fraction}} of it and at most {{rule.rest_max}}. Random frames must carry at most {{rule.random_max}}. The rule applies in both count cells. The original project's verdict was that the rule holds for the route through the six transforms and holds only in part for the route through {{demo.l9_transform_short}} and {{demo.l9_transform_long}} alone, because it recorded a share of {{rule.recorded_rest}} for the rest in count:100 through those two transforms.

Steering one unit by a dose

Numbers per layer

FVU means fraction of variance unexplained. It is squared reconstruction error divided by squared deviation from the per-dimension mean of each held-out split. The state FVU is in raw residual units at the two state sites. The MLP FVU is in raw MLP output units.

Two kinds of numbers appear in Figure {{fig|layers}}, and the figure keeps them apart. This repository measured the state FVU at both sites and the MLP FVU with its reader on all tokens of the original project's four held-out splits. The splits contain {{fvu.tokens}} tokens per layer, of which {{fvu.position_0_tokens}} are at position 0. Position 0 means the first position of each sequence. The original project recorded the MLP FVU at training, the MLP transforms on per token and the MLP transforms alive on a held-out shard of each layer's training capture, with position 0 included. The two MLP FVU series differ because they are measured on different tokens.

Not recomputable. The held-out activations are not published, so users cannot recompute these exact numbers. The shards behind the training-time numbers were deleted afterwards, and this repository did not repeat those measurements.

Position 0 matters for the state dictionary at some layers: at layer {{fvu.example_layer}}, resid_mid, the state FVU is {{fvu.l6_mid_with_p0}} with position 0 and {{fvu.l6_mid_dropped}} without it. The original project dropped position 0 during state dictionary training and included it during MLP dictionary training. The reader's capture drops it.

Spliced-in loss

Spliced-in loss is the increase in next-token cross-entropy when a dictionary reconstruction replaces the true activation in the forward pass, one layer and one dictionary at a time. The original project measured it in nats on text with clean cross-entropy {{splice.clean_ce}}. This repository did not repeat the measurement.

The original project used FineWeb-Edu rows outside the training mixture, taking the first {{splice.documents}} documents of at least {{splice.min_tokens}} tokens and the first {{splice.tokens_each}} tokens of each. Position 0 was not replaced. Loss was averaged over positions {{splice.first_position}} to {{splice.last_position}}, or {{splice.positions}} positions. The dictionaries are the released ones. The MLP result for layer {{model.last_layer}} comes from a separate measurement by the original project on the same kind of web text.

In the original project's comparison on the same text, the earlier set had smaller increases at all {{model.layers}} state layers and MLP layers {{model.first_layer}} to {{mlp.penalty_main_last_layer}}. For the state dictionary at layer {{splice.example_layer}}, it recorded {{splice.l9_state_here}} here against {{splice.l9_state_earlier}} for the earlier set. At layer {{model.last_layer}}, the released MLP dictionary had the smaller increase, {{splice.l23_mlp_here}} against {{splice.l23_mlp_earlier}} for the earlier set.

A second set, for Qwen3.5-4B

A second set for {{b4.model}}, with {{b4.layers}} layers and width {{b4.width}}, is published at mconcat/statescope-qwen3.5-4b and occupies about {{b4.total_gib}} GiB. It uses the same forms, reader and folder layout, with ALWAYS_ON.json added and {{b4.transforms}} MLP transforms per layer. Each state dictionary has {{b4.groups}} groups of {{b4.group_size}} directions, with {{b4.active}} active per token, as in the 0.8B set.

It is a copy made on {{b4.copied}} of what the original project trained with one seed, rather than a frozen configuration like the 0.8B set. There is no demonstration for it; demo/line_count.py is for 0.8B only. The demonstration and the 0.8B numbers do not carry over to this set.

The limits of this set are different from those of the 0.8B set, and several are larger.

Limits

These limits belong to the results above and should be read with them.

One model and one dictionary seed
The set covers one model, 0.8B, and one dictionary seed. The demonstration covers the same model and seed, with texts wrapped to a fixed width.
No dictionaries for the mixers
There are no dictionaries for the mixers, which are the GatedDeltaNet and attention sublayers. The count of characters is carried inside the L9 mixer, so that step of the chain is measured in the model's own mixer and head {{demo.head}}, not in a dictionary.
An easy task with dedicated MLP neurons
This is an easy task for which the model has dedicated MLP neurons. The demonstration is not evidence that dictionary units are better than neurons.
The script does not search
The script uses the original project's chosen transform, group and head and re-measures their effects. It does not search for them.
Group {{demo.l9_group}} is dense
State group {{demo.l8_group}} is sparse, but not every group is sparse. Some groups encountered by the original project on this task are dense {{demo.frame_dim}}-dimensional coordinates active on most tokens. They carry information in their coordinates. Group {{demo.l9_group}} is one of these dense groups, not a sparse feature.
The frame is not the only route, and the pass rule holds only in part
The frame of group {{demo.l9_group}} is not the only route from the L9 mixer to the answer. The registered pass rule for that link holds for the route through the six transforms and holds only in part for the route through transforms {{demo.l9_transform_short}} and {{demo.l9_transform_long}} alone.
Rounding of single-item margins
Single-item margins of dictionary swaps are reproducible only to about {{demo.margin_repro}}. Shares are reproducible only to about {{demo.share_repro}}. A patched tensor is rounded to bf16. A {{demo.relative_difference}} relative difference between implementations flips some rounded elements. Newer library versions moved shares by up to about {{check.new_share_about}}. A pre-activation within float rounding of its hard threshold can be on in one computation and off in another.
The trainers are not in the repository
Training cannot be reproduced because the trainers for this set are not in the repository. Porting them is planned. No full-length training run was repeated for either design.
Numbers that cannot be recomputed from the published files
The per-layer reconstruction numbers and the spliced-in loss cannot be reproduced because the held-out activations and texts behind them are not published. The original project recorded MLP FVU, transforms on per token and transforms alive at training on a held-out shard of each layer's training capture. The shards were subsequently deleted, including the shard for layer {{model.last_layer}}'s separate run. This repository did not repeat the original project's training-time MLP held-out measurements or the spliced-in loss measurements.
The earlier set had smaller spliced-in loss
In the original project's comparison on the same text, the earlier set had smaller increases at all {{model.layers}} state layers and MLP layers {{model.first_layer}} to {{mlp.penalty_main_last_layer}}.
One machine and one GPU model
Every comparison ran on one machine with one RTX 5090. A second machine and a different GPU model were not checked.

Using it

Python 3.12 or newer is required. In a checkout of the code, install the reader with the packages that capture and the demonstration need, and download the weights. Replace <folder> with the destination.

sh
pip install -e '.[model]'
hf download mconcat/statescope-qwen3.5-0.8b --local-dir <folder>

The reader is the single file src/statescope/reader.py. It can be copied next to the weights. capture returns resid_mid, mlp_out and resid_post for the requested layer with position 0 dropped.

python
{{reader.example}}

The first command checks all {{set.files}} files against the manifest. The second re-runs the traced line-count chain; it ran in under two minutes on one RTX 5090, including model loading.

sh
python demo/verify_release.py --release <folder>
python demo/line_count.py --release <folder> --device cuda:0 --out <folder for the result>

Without flash-linear-attention, transformers silently uses a slow GatedDeltaNet reference implementation. Drop position 0 when measuring with the state dictionary. The capture function already does this.
